```markdown
## Obiettivo
Due forme dalla stessa build:
1. **Installata** — `WinGetStudio-Setup.exe` (Inno Setup): collegamento nel menu Start, icona sul Desktop facoltativa, disinstallazione da Impostazioni. Diventa l'installer del manifesto winget.
2. **Portable** — `WinGetStudio.exe`: come oggi, un file solo che si aggiorna da sé.

## Stato attuale (verificato su `main`)
- `src/build.ps1` produce un solo exe con manifest `requireAdministrator`: l'app gira **sempre elevata**.
- Manifesto winget: `InstallerType: portable`, `ElevationRequirement: elevatesSelf`.
- `App.Update.ps1` prende il **primo** asset `*.exe` della release e verifica lo SHA-256 (`digest`) quando GitHub lo espone.
- `Test-IsWinGetPortable` spegne l'auto-update della copia portable gestita da winget.
- Dalla 1.10.2 c'è una CI su GitHub Actions (test + build non firmata); la firma resta locale.

## Correzioni alla specifica
1. **Solo installazione per macchina.** L'app è sempre elevata: un'installazione per utente avviata o aggiornata da un processo elevato finisce nel profilo dell'amministratore quando questo non è l'utente connesso (il caso per cui esiste `Test-ElevatedUserMismatch`). Quindi `PrivilegesRequired=admin`, cartella in `Program Files`, una sola voce nel manifesto: metà della matrice di test sparisce.
2. **Niente canale "winget" separato né marcatore d'origine nel registro.** Inno scrive la voce di disinstallazione `{AppId}_is1`, ed è da lì che winget legge la versione installata. Con `AppsAndFeaturesEntries` coerenti nel manifesto (`ProductCode: <AppId>_is1`, `DisplayName`, `Publisher`) una copia installata da winget e aggiornata dall'app resta allineata per winget. I canali sono due: **installata** e **portable**.
3. **Niente processo supervisore.** La copia installata scarica `WinGetStudio-Setup.exe`, ne verifica lo SHA-256, lo avvia con `/SILENT /CLOSEAPPLICATIONS /LOG="%TEMP%\WinGetStudio-update.log"` e si chiude. Inno sostituisce i file e rilancia l'app da una voce `[Run]` (`Flags: nowait`); il setup è già elevato, quindi niente secondo UAC. Gli errori li mostra il wizard (`/SILENT`, non `/VERYSILENT`) e restano nel log.
4. **Non contare sull'ordine degli asset.** L'API delle release non lo garantisce, e le copie fino alla 1.10.x prendono il primo `.exe`: con due `.exe` nella stessa release una vecchia copia portable potrebbe sostituirsi con l'installer. Rilascio in due tempi: prima una versione con il **solo** exe portable che sceglie l'asset per nome, l'installer dalla successiva.
5. **Migrazione winget portable → Inno.** La versione di passaggio dichiara `UpgradeBehavior: uninstallPrevious`, così winget toglie la copia portable (e il suo alias) prima di installare. Da provare in Windows Sandbox prima di inviare il manifesto.
6. **Firma.** Exe, setup **e disinstallatore** (`SignTool` + `SignedUninstaller=yes`) firmati con la chiave originale, quella di `assets/WinGetStudio-codesign.cer`. Mai una seconda chiave con lo stesso nome.
7. **CI.** La specifica diceva "nessuna pipeline": ora c'è. Deve compilare anche il setup (`choco install innosetup` sul runner) e caricarlo come artefatto non firmato.
8. **Defender.** Un installer che contiene un exe ps2exe può riattivare il falso positivo già documentato: al primo rilascio inviare a Microsoft entrambi i file.

## Disegno
- **Build:** `build.ps1` produce `WinGetStudio.exe`, poi `iscc` ne fa `WinGetStudio-Setup.exe`. `AppId` fisso (un GUID, per sempre), `AppVersion` da `$AppVersion`.
- **Canale:** exe dentro la cartella registrata in `{AppId}_is1` (`InstallLocation`) → installata; altrimenti portable. La vecchia copia portable di winget resta riconosciuta da `Test-IsWinGetPortable`.
- **Aggiornamento:** asset scelto per **nome**, mai per posizione; un asset senza `digest` non è verificato e non si avvia.
- **Disinstallazione:** toglie programma e collegamenti, lascia `HKCU\Software\WinGetStudio` salvo decisione contraria.

## Verifiche prima del rilascio (Windows Sandbox, mai sull'installazione di tutti i giorni)
- Suite di test e build in CI, con il setup tra gli artefatti.
- Setup: installazione, avvio, aggiornamento dall'app, disinstallazione.
- `winget install --manifest <locale>`, aggiornamento dall'app, poi `winget list FedeB2160.WinGetStudio` mostra la versione nuova e `winget upgrade` non la ripropone.
- Migrazione dalla copia portable di winget con `uninstallPrevious`: nessuna copia doppia, alias rimosso.
- Portable da GitHub: controllo release, SHA-256, sostituzione, riavvio.
```

```powershell
# Esegue un comando di LETTURA (search, list, upgrade senza --id, pin list) e restituisce
# l'esito insieme ai dati: { Success, Rows, ExitCode, Output }. Prima un errore di winget
# diventava una lista vuota, e la UI diceva "nessun aggiornamento" a winget rotto.
# Success = exit 0, e solo allora si parsa la tabella; quando un exit non-zero e' un
# risultato valido lo decide il chiamante (Get-WinGetSearch).
# $wingetPath: il percorso risolto UNA VOLTA da Get-WinGetPath, passato nelle -Vars del job.
# NON "& winget": quella forma risolve il NOME a ogni chiamata, quindi dipende dal PATH e
# dall'alias di esecuzione app, che sotto un account elevato diverso da quello interattivo
# possono non esserci.
# -Width alto: senza console (exe -noConsole) o con finestra stretta Out-String manderebbe
# a capo le righe alla larghezza dell'host, spezzando la tabella.
# Non Invoke-WinGet: quella passa per cmd, e il testo di una ricerca lo scrive l'utente in un
# processo elevato. Qui gli argomenti restano un array.
function Invoke-WinGetRead([string[]]$Arguments, [int]$MaxColumns = 0) {
    $raw = ''
    try {
        $raw = & $wingetPath @Arguments 2>&1 | Out-String -Width 4096
        $exitCode = [int]$LASTEXITCODE
    }
    catch {
        $raw = $_.Exception.Message
        $exitCode = -1
    }
    # Assegnazione diretta di @(...), non "$rows = if (...) { @(...) }": l'if srotolerebbe una
    # tabella di UNA riga nei suoi campi.
    $rows = @()
    if ($exitCode -eq 0) { $rows = @(Get-WinGetTable $raw -MaxColumns $MaxColumns) }
    return [PSCustomObject]@{
        Success  = ($exitCode -eq 0)
        Rows     = [object[]]$rows
        ExitCode = $exitCode
        Output   = [string]$raw
    }
}

# Ricerca nel catalogo. Colonne: Nome | Id | Versione | [Corrispondenza] | [Origine] —
# si usano solo le prime tre, le altre compaiono o no a seconda del risultato.
#
# --source winget: interroga il solo indice LOCALE (~0.4s). Con msstore la stessa ricerca
#   va in rete e passa a ~5s, troppo per aggiornare l'elenco mentre si digita.
# --count: senza un tetto una query di 2-3 lettere torna oltre mille righe (misurato:
#   "ab" -> 1288) e la griglia annega.
# 0x8A150014 (APPINSTALLER_CLI_ERROR_NO_APPLICATIONS_FOUND) e' "nessuna corrispondenza": un
#   risultato vuoto, non un errore. Solo qui: list e upgrade senza filtri elencano tutto
#   l'installato e quel codice non lo producono. L'exit si normalizza a 32 bit senza segno
#   prima del confronto, come in Get-UpdateStatus.
function Get-WinGetSearch([string]$Query, [bool]$IncludeStore = $false, [int]$Count = 25) {
    if ([string]::IsNullOrWhiteSpace($Query)) {
        return [PSCustomObject]@{ Success = $true; Rows = [object[]]@(); ExitCode = 0; Output = '' }
    }
    $wgArgs = @('search', $Query, '--count', "$Count", '--accept-source-agreements')
    if (-not $IncludeStore) { $wgArgs += @('--source', 'winget') }
    $read = Invoke-WinGetRead -Arguments $wgArgs
    if ((([int64]$read.ExitCode) -band 0xFFFFFFFFL) -eq 0x8A150014L) { $read.Success = $true }
    if (-not $read.Success) { return $read }

    $results = New-Object System.Collections.ArrayList
    foreach ($f in $read.Rows) {
        [void]$results.Add([WgtRow]@{ Selected = $false; Name = $f[0]; Id = $f[1]; Version = $f[2] })
    }
    $read.Rows = $results.ToArray()
    return $read
}

# ID dei pacchetti con un pin. Colonne: Nome | Id | Versione | Origine | Tipo di pin —
# serve solo l'ID, il tipo (Pinning / Blocking / Gating) non cambia cosa mostriamo.
# Senza pin winget stampa una frase, nessuna tabella ed exit 0: Rows vuoto e Success vero.
function Get-WinGetPins {
    # -MaxColumns 3 e' obbligatorio: l'ultima intestazione ("Tipo di pin") contiene spazi
    # e senza il limite ogni riga verrebbe scartata come disallineata.
    $read = Invoke-WinGetRead -Arguments @('pin', 'list', '--accept-source-agreements') -MaxColumns 3
    if (-not $read.Success) { return $read }
    $ids = New-Object System.Collections.ArrayList
    foreach ($f in $read.Rows) { [void]$ids.Add($f[1]) }
    $read.Rows = $ids.ToArray()
    return $read
}

# Inventario dei pacchetti installati. Colonne: Nome | Id | Versione | [Origine].
# ATTENZIONE: la quarta colonna qui e' Origine, NON "Disponibile" come in upgrade.
# Include anche cio' che non e' stato installato con winget: quei pacchetti hanno un Id
# di tipo "ARP\Machine\X64\Nome Prodotto" (con spazi dentro, del tutto legittimi) e
# Origine vuota.
function Get-WinGetInstalled {
    $read = Invoke-WinGetRead -Arguments @('list', '--accept-source-agreements')
    if (-not $read.Success) { return $read }
    $results = New-Object System.Collections.ArrayList
    foreach ($f in $read.Rows) {
        # "> 8.12.30.21" -> "8.12.30.21": il ">" segnala che esiste un aggiornamento, e di
        # quello si occupa la scheda Updates.
        [void]$results.Add([WgtRow]@{ Selected = $false; Name = $f[0]; Id = $f[1]; Version = ($f[2] -replace '^>\s*', '') })
    }
    $read.Rows = $results.ToArray()
    return $read
}

# Elenco degli upgrade disponibili. Colonne: Nome | Id | Versione | Disponibile | [Origine].
function Get-WinGetUpgrades([bool]$IncludeUnknown = $false) {
    # --include-unknown: include pacchetti con versione installata sconosciuta (opzionale,
    #   la spunta in alto lo comanda: senza, winget elenca solo cio' di cui sa la versione)
    # --accept-source-agreements: evita prompt interattivi al primo uso della sorgente
    $wgArgs = @('upgrade', '--accept-source-agreements')
    if ($IncludeUnknown) { $wgArgs += '--include-unknown' }
    $read = Invoke-WinGetRead -Arguments $wgArgs
    if (-not $read.Success) { return $read }
    $results = New-Object System.Collections.ArrayList
    foreach ($f in $read.Rows) {
        if ($f.Count -lt 4) { continue }   # senza la colonna Disponibile non e' un upgrade
        [void]$results.Add([WgtRow]@{ Selected = $false; Name = $f[0]; Id = $f[1]; Version = $f[2]; Available = $f[3] })
    }
    $read.Rows = $results.ToArray()
    return $read
}
```
